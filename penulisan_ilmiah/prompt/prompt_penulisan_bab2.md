PROMPT 5 -- Subbab 2.5 Sistem Manajemen Kuota Sesi
================================================================

Bertindaklah sebagai asisten penulis akademis untuk Penulisan Ilmiah (PI) Diploma 3.

Tugas: Tulis isi subbab 2.5 Sistem Manajemen Kuota Sesi untuk Bab 2 Tinjauan Pustaka PI saya.

Konteks sistem DETAIL (wajib dipahami sebelum menulis):
- Setiap siswa mendapat kuota 8 pertemuan per periode pembayaran.
- Presensi "Hadir" -> kuota berkurang 1 (8 menjadi 7, dan seterusnya).
- Presensi "Tidak Hadir" atau "Kelas Diliburkan" -> kuota TIDAK berkurang.
- Kuota = 0 -> sistem memunculkan peringatan tagihan kepada orang tua.
- Jika admin tetap input "Hadir" meski kuota 0 -> kuota menjadi negatif
  (-1, -2, dst) sebagai penanda tunggakan layanan.
- Kuota negatif -> memicu notifikasi teguran khusus kepada orang tua.

Panduan isi:
- Konsep manajemen kuota dalam konteks layanan berbasis sesi/pertemuan [n].
- Logika pengurangan kuota berdasarkan status kehadiran sesuai konteks di atas.
- Mekanisme kuota nol dan kuota negatif beserta implikasinya terhadap notifikasi
  dan administrasi pembayaran.
- Alasan pemilihan mekanisme ini: fleksibilitas bagi orang tua sekaligus kontrol
  administrasi bagi pengelola bimbel.

PROMPT 6 -- Subbab 2.6 Logika Kalender Dinamis dan Estimasi Jadwal
================================================================

Bertindaklah sebagai asisten penulis akademis untuk Penulisan Ilmiah (PI) Diploma 3.

Tugas: Tulis isi subbab 2.6 Logika Kalender Dinamis dan Estimasi Jadwal untuk
Bab 2 Tinjauan Pustaka PI saya.

Konteks sistem DETAIL (wajib dipahami sebelum menulis):
- Setiap siswa memiliki jadwal rutin 2 hari per minggu (contoh: Senin dan Kamis).
- Setelah mendaftar dan membayar, sistem otomatis menghitung estimasi tanggal
  pertemuan ke-8, disebut "Hari-H", berdasarkan jadwal rutin siswa.
- Hari-H menjadi basis pengiriman notifikasi tagihan: H-7, H-3, H-1, dan Hari-H.
- Jika presensi "Tidak Hadir" atau "Kelas Diliburkan" -> Hari-H otomatis bergeser
  mundur ke jadwal berikutnya karena sesi tersebut tidak dihitung sebagai sesi terpakai.
- Logika ini memastikan pengingat tagihan selalu akurat meski ada ketidakhadiran atau libur.

Panduan isi:
- Konsep kalender dinamis dalam sistem informasi: sistem yang menyesuaikan kalkulasi
  tanggal otomatis berdasarkan kondisi data yang berubah [n].
- Perbedaan kalender statis (dihitung sekali saat pendaftaran, tidak berubah) vs
  kalender dinamis (dihitung ulang setiap ada perubahan kondisi presensi).
- Algoritma estimasi jadwal: penghitungan tanggal pertemuan ke-N berdasarkan
  hari rutin dengan melompati hari-hari yang berstatus tidak hadir.
- Logika pergeseran Hari-H dan hubungannya dengan sistem notifikasi tagihan otomatis.

WAJIB terikat ke detail sistem Ruang Les.

PROMPT 14 -- Subbab 2.18 Black Box Testing dan 2.19 User Acceptance Test (UAT)
================================================================

Bertindaklah sebagai asisten penulis akademis untuk Penulisan Ilmiah (PI) Diploma 3.

Tugas: Tulis isi subbab 2.18 Black Box Testing dan 2.19 User Acceptance Test
untuk Bab 2 Tinjauan Pustaka PI saya.

Konteks: Pengujian sistem dilakukan dua tahap: Black Box Testing untuk memvalidasi
fungsionalitas, dan UAT untuk memastikan sistem sesuai kebutuhan pengguna nyata
(Admin, Mentor, Orang Tua).

Subbab 2.18 Black Box Testing:
- Definisi: metode pengujian dari sudut pandang pengguna tanpa memeriksa kode [n].
- Karakteristik: fokus pada input yang diberikan dan output yang diharapkan.
- Kelebihan: dapat dilakukan tanpa pengetahuan teknis kode.
- Teknik: Equivalence Partitioning dan Boundary Value Analysis [n].
- Peran: menguji seluruh fitur sistem terhadap spesifikasi yang ditetapkan.

Subbab 2.19 User Acceptance Test (UAT):
- Definisi: pengujian penerimaan oleh pengguna akhir sebelum sistem diimplementasikan [n].
- Karakteristik: dilakukan pengguna nyata menggunakan skenario penggunaan aktual.
- Perbedaan dengan Black Box: Black Box = validasi teknis fungsionalitas,
  UAT = penerimaan dan kepuasan pengguna.
- Peran: dilakukan bersama perwakilan Admin, Mentor, Orang Tua untuk memvalidasi
  kesesuaian sistem dengan kebutuhan operasional nyata.
